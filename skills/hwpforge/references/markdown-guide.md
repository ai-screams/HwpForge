# 한국어 마크다운 작성 규칙

HwpForge가 올바르게 변환하려면 GFM(GitHub Flavored Markdown) 표준을 따르되, 한국어 문서 특성에 맞는 규칙을 지켜야 합니다.

## YAML 프론트매터

모든 문서의 맨 앞에 YAML 블록으로 메타데이터를 지정합니다.

```yaml
---
title: "문서 제목"
author: "작성자 이름"
date: "2026-03-09"
---
```

지원 필드:

| 필드       | 설명                                                         | 예시                                         |
| ---------- | ------------------------------------------------------------ | -------------------------------------------- |
| `title`    | 문서 제목                                                    | `"AI 기반 시스템 구축 제안서"`               |
| `author`   | 작성자                                                       | `"홍길동"`                                   |
| `date`     | 작성일                                                       | `"2026-03-09"`                               |
| `metadata` | 문서 속성 — 중첩 키 `subject`/`keywords`/`modified`만 인식됨 | `metadata: {subject: "…", keywords: [a, b]}` |

`template` 키는 파싱되어 저장·왕복되지만 스타일 선택에는 영향이 없습니다(현재 inert, 항상 기본 스타일 사용). 위 표에 없는 키(`template` 제외 — 예: `preset`, `organization`)는 최상위든 `metadata:` 아래든 파싱 후 조용히 무시됩니다 — 에러는 나지 않지만 아무 효과도 없습니다. 스타일은 프론트매터가 아니라 `convert --preset` 플래그로 지정합니다(CLI는 `default`/`modern`/`classic`/`latest` 네 프리셋을 모두 받아들입니다). 프론트매터가 없으면 `default` 프리셋이 적용됩니다.

## 제목 계층 구조

```markdown
# 문서 제목 (H1 — 표지 또는 최상위 제목)

## 1. 장 제목 (H2 — 주요 섹션)

### 1.1 절 제목 (H3 — 하위 섹션)

#### 1.1.1 항 제목 (H4 — 세부 항목)
```

주의사항:

- 번호는 마크다운에서 수동 작성 (`## 1.`, `### 1.1`)
- 계층을 건너뛰지 말 것 (H2 다음 바로 H4 금지)

## GFM 표 문법

```markdown
| 열1    | 열2    | 열3    |
| ------ | ------ | ------ |
| 데이터 | 데이터 | 데이터 |
| 데이터 | 데이터 | 데이터 |
```

정렬 지정:

```markdown
| 왼쪽 정렬 | 가운데 정렬 | 오른쪽 정렬 |
| :-------- | :---------: | ----------: |
| 텍스트    |   텍스트    |        숫자 |
```

한국어 표 작성 팁:

- 헤더 셀에 **볼드** 사용 가능: `| **항목** |`
- 합계 행에는 볼드 강조: `| **합계** | **100%** |`
- 숫자는 오른쪽 정렬 권장

## 이미지 삽입

```markdown
![대체 텍스트](./images/figure1.png)

**[그림 1] 시스템 아키텍처**
```

경로 규칙:

- 상대 경로와 절대 경로 모두 쓸 수 있지만, **마크다운 파일이 있는 디렉터리 안(하위 포함)으로 정규화되는 경로만** 임베드됩니다. 그 디렉터리 밖을 가리키는 절대 경로나 `../`로 벗어나는 상대 경로는 경고만 남기고 조용히 제외됩니다(에러 아님) — 공유 에셋 폴더의 이미지를 쓰려면 문서 디렉터리 안으로 복사한 뒤 참조하세요.
- `http(s)://` 원격 URL은 지원하지 않습니다(네트워크 접근 금지, 경고 후 제외).
- 지원 형식(파일 내용의 매직바이트로 판별): PNG, JPG/JPEG, GIF, BMP, WMF, EMF. **SVG는 지원하지 않습니다.**

이미지 디렉토리를 마크다운 파일과 함께 유지하세요:

```
project/
├── document.md
└── images/
    ├── figure1.png
    └── figure2.png
```

### `data:` URI로 인라인 임베드

표준 입력(`hwpforge convert - …`)이나 MCP로 마크다운을 인라인 텍스트로 넘길 때는 상대/절대 경로의 기준이 될 디렉터리가 없어 파일 경로로는 이미지를 찾을 수 없습니다. 이때는 base64로 인코딩한 `data:` URI를 쓰면 파일 없이 바로 임베드됩니다 — base_dir가 없는 입력에서 이미지를 넣을 수 있는 유일한 방법입니다:

```markdown
![대체 텍스트](data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA...)
```

## 섹션 구분

`---` (하이픈 3개 이상, thematic break)는 페이지나 섹션 구분으로 변환되지 **않습니다** — 그대로 리터럴 텍스트 `"---"` 문단으로 본문에 남습니다. 장(chapter) 사이에 실제로 새 HWPX 섹션(필요하면 새 쪽에서 시작)을 나누려면 `<!-- hwpforge:section -->` 라는 전용 HTML 주석을 써야 합니다 — 디코더가 유일하게 허용하는 raw HTML이며, 다른 raw HTML은 전부 변환 오류(`MD_DECODE_FAILED`)가 됩니다. 정의 목록(`용어` 다음 줄 `: 정의`)도 같은 오류입니다.

```markdown
## 제1장 서론

본문 내용...

<!-- hwpforge:section -->

## 제2장 현황 분석

본문 내용...
```

주의:

- 주석의 앞뒤 공백은 무시되지만(트리밍 후 비교), 그 안의 오타나 다른 raw HTML은 전부 오류로 실패합니다. 반드시 빈 줄로 둘러싸고, 표 셀 안에서는 쓸 수 없습니다.
- 장 사이를 시각적으로만 나누고 싶을 뿐 새 섹션이 필요 없다면 `---`를 쓰지 말고 그냥 생략하세요 — `---`에 대응하는 장식용 구분선 문법은 없습니다.

## 강조 문법

```markdown
**볼드 텍스트** — 중요 키워드, 표 헤더
_이탤릭 텍스트_ — 영문명, 외래어 (한국어에는 거의 미사용)
~~취소선~~ — 삭제된 내용
`코드` — 시스템 명칭, 파라미터, 명령어
```

## 목록 문법

순서 없는 목록:

```markdown
- 항목 1
- 항목 2

  - 하위 항목 (공백 2칸 들여쓰기)
  - 하위 항목
```

순서 있는 목록:

```markdown
1. 첫 번째
2. 두 번째
3. 세 번째
```

공문서 번호 체계 (수동 작성):

```markdown
1. 첫째 수준

   가. 둘째 수준

   1. 셋째 수준

      가) 넷째 수준
```

## 각주·미주 문법

```markdown
본문 내용입니다.[^1] 추가 내용.[^ref] 미주로 보낼 내용입니다.[^e1]

[^1]: 각주 내용 (해당 쪽 하단에 자동 배치됨)

[^ref]: 참고문헌 각주

[^e1]: 미주 내용 (문서 끝에 자동 배치됨)
```

라벨이 `e` + 숫자(`[^e1]`, `[^e12]`, 대소문자 무관)인 것은 **미주로**, 그 외 라벨은 **각주로** 변환됩니다. 둘 다 HWPX 변환 시 한글 각주/미주 형식으로 자동 변환됩니다.

각주·미주 정의 본문에는 글자와 강조로 된 문단만 쓸 수 있습니다(들여쓴 둘째 문단은 됨). 정의 안에 목록·인용·코드 블록을 넣으면 `MD_DECODE_FAILED`(exit 2)로 변환이 실패합니다.

## 코드 블록

````markdown
```python
# 코드 블록 예시
def hello():
    print("안녕하세요")
```
````

정부 문서에서는 주로 시스템 명령어, SQL, 설정값 표시에 사용합니다.

## 특수문자 처리

마크다운에서 이스케이프가 필요한 문자:

| 문자 | 이스케이프 | 용도                                |
| ---- | ---------- | ----------------------------------- |
| `*`  | `\*`       | 별표를 볼드/이탤릭 아닌 문자로 사용 |
| `_`  | `\_`       | 밑줄 문자 그대로 사용               |
| `[`  | `\[`       | 대괄호를 링크 아닌 문자로 사용      |
| `#`  | `\#`       | 샵을 제목 아닌 문자로 사용          |

한국어 특수문자는 이스케이프 없이 직접 입력합니다: ㄱㄴㄷ, ◆◇●, ※. 원형 숫자도 그대로 통과하지만, 목록 번호에는 원형 숫자 대신 마크다운 순서 목록(`1.` `2.`)이나 일반 숫자를 쓰세요.

## 인코딩 및 개행

- 파일 인코딩: UTF-8 (BOM 없음)
- 줄바꿈: LF (Unix 방식) 권장, CRLF도 지원
- 문단 구분: 빈 줄 1개

빈 줄 없이 이어진 줄은 HWPX에서 한 문단이 되지만, **줄바꿈은 공백 한 칸으로** 바뀝니다(`가나` 줄 + `다라` 줄 → `가나 다라`). 한 문단은 한 줄에 쓰거나, 어절 경계에서만 줄을 나누세요.

```markdown
이 문장은 마크다운에서 두 줄로 작성되었지만
HWPX에서는 공백 한 칸으로 이어진 하나의 문단이 됩니다.

빈 줄이 있어야 새 문단으로 구분됩니다.
```
