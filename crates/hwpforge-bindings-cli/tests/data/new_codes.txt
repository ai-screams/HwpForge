# Frozen (command, code, exit, hint) contract for call sites with NO
# pre-migration source to audit: forward-assigned contracts without legacy
# precedent, including intentionally CLI-unreachable ops codes — a command
# the migration itself introduced, or an `OpsCode` a guard (clap, a typed
# argument list, …) keeps this CLI from ever reaching, but which still
# needs a frozen row for cross-frontend parity (see the
# `insert-para INSERT_TEXT_REQUIRED` row below — reachable through MCP, not
# through this CLI at all) — plus one more group: a hint this CLI
# deliberately replaced, recorded under "의도적 안내 개선" at the end of
# this file. `legacy_codes.txt` (same directory) is the pre-W3-migration
# snapshot; `src/compat.rs`'s `snapshot_rows()` reads both files, and the
# two stay disjoint except for the pairs `SUPERSEDED_LEGACY_HINTS` names
# (see its header note). Same column format as `legacy_codes.txt`
# (`command<TAB>code<TAB>exit<TAB>hint`); "frozen from the commit that adds
# it" here means the same thing "frozen from the pre-migration source"
# means there — once a row lands, `src/compat.rs`'s `TABLE` must keep
# producing it.
#
# ── `validate` — new command, no legacy CLI to audit ────────────────────
# `validate` did not exist before this migration (W5b); it is wired
# straight against `hwpforge::ops::validate`. READ-FIRST like the "(all
# others)" group in `legacy_codes.txt`'s precedence note:
# `check_file_size`/`std::fs::read` run before `ops::validate` is ever
# called, and there is no argument to validate ahead of that.
validate	DECODE_FAILED	2	-
validate	FILE_READ_FAILED	1	-
validate	JSON_SERIALIZE_FAILED	2	-
#
# ── `insert-para INSERT_TEXT_REQUIRED` — reachable only post-migration ──
# Clap's `#[arg(long = "text", required = true)]` already refuses an empty
# `--text` list before `run_insert` is ever called, so the pre-migration
# CLI never had a call site for `ops::edit::insert_para`'s own
# `InsertTextRequired` rejection (reachable only through a frontend with no
# equivalent guard, e.g. MCP) — audit finding: an unrouted new code
# silently took `exit_code`'s fallback (2, the codec-failure class) instead
# of 1. Exit 1, the argument-error class every other `insert-para`/
# `delete-para` row in `legacy_codes.txt` uses.
insert-para	INSERT_TEXT_REQUIRED	1	-
#
# ── `DecodeFailed` for delete-para/insert-para/fill/set-cell/stamp-plan/
# stamp — a promotion, not a legacy-audit gap ───────────────────────────
# Each of these six decodes an existing HWPX package, so `DecodeFailed` was
# always reachable for them; none had a `TABLE` row, so `cli_error` fell
# through to its `None` branch (`code.as_str()` + `err.hint()`) instead of
# an explicit one. C4 reverse-check follow-up: promoted to explicit rows
# so the forward compatibility check can see the real, live divergence
# `KNOWN_CODE_DIVERGENCE` already excused for them (CLI: DECODE_FAILED,
# MCP: DECODE_ERROR) — the missing row was hiding it from that check, not
# a case where the two frontends happened to agree. String and exit are
# unchanged from what the fallback already produced (pinned by
# `structural_commands_decode_failed_output_is_unchanged_by_their_new_table_rows`
# before and after the row landed) — this is a promotion of an existing
# output to an explicit row, not new behavior, hence here and not a
# retroactive edit to `legacy_codes.txt` (frozen historical snapshot; see
# its own header).
delete-para	DECODE_FAILED	2	Check that the file is a valid HWPX document
insert-para	DECODE_FAILED	2	Check that the file is a valid HWPX document
fill	DECODE_FAILED	2	Check that the file is a valid HWPX document
set-cell	DECODE_FAILED	2	Check that the file is a valid HWPX document
stamp-plan	DECODE_FAILED	2	Check that the file is a valid HWPX document
stamp	DECODE_FAILED	2	Check that the file is a valid HWPX document
#
# ── 의도적 안내 개선 — `legacy_codes.txt` 의 힌트를 대체한다 ────────────
# 아래 행들은 `legacy_codes.txt` 에 같은 `(command, code)` 행이 이미 있다.
# 그쪽은 동결된 과거 기록이라 고치지 않고, 오늘 CLI 가 내는 힌트를 여기에
# 적는다. `src/compat.rs` 의 `SUPERSEDED_LEGACY_HINTS` 가 짝을 이루며,
# 옛 문구를 아직도 내보내는 소스가 있으면 그 목록의 검사가 실패한다.
# code 와 exit 는 그대로다 — 바뀌는 것은 힌트뿐.

# 하나만 말했다. `commands/convert.rs` 의 사전 검사와 `ops::convert_md` 의

# 전부 통과한다.
