# Frozen (command, code, exit, hint) contract, extracted by hand from every
# `CliError::new("<CODE>", ...)` (+ `.with_hint("<literal>")`,
# `.exit(json_mode, N)`) call site in `src/commands/*.rs` and `src/error.rs`
# on the pre-W3-migration tree (branch `feat/cli-ops-migration`, base
# `5ff81af`, which already contains W2/bindings-mcp's ops migration). One
# `command<TAB>code<TAB>exit<TAB>hint` row per distinct call-site *shape* —
# sorted by command, then code, then exit, then hint. `audit-hwp5` and
# `census-hwp5` are analysis commands with no `ops` counterpart (common.md
# W3 brief) and are audited here too because they still construct `CliError`
# directly and this file's job is "every code in the source", not "every
# code W3 touches". `shared` is `error.rs`'s `check_file_size` — called
# directly from nearly every other command's `run()` (grep: every command
# file except `templates.rs` and `schema.rs`), so `INPUT_TOO_LARGE` is not
# attributed to one command.
#
# hint column (exact, not a category — `src/compat.rs`'s inventory test
# compares `TABLE`'s hint field against this text byte-for-byte, per the W3
# adversarial-review addendum: a prior lane's snapshot recorded only code
# literals and shipped three wrong hints undetected):
#   `-`              no `.with_hint(...)` at this call site.
#   <literal text>    the exact `.with_hint("...")` argument, byte-for-byte
#                      (format!() calls that only interpolate *static*
#                      strings, e.g. `format!("Preset '{preset}' not found")`
#                      for the *message* — not the hint — still count as
#                      literal for the hint column when the hint itself has
#                      no per-call substitution).
#   dynamic:<what>     the hint text embeds a per-call value (an
#                      available-fields list, a section count, a table's
#                      cell count, a conditional anchor coordinate) that no
#                      flat row can hold verbatim; `<what>` names what.
#                      `src/compat.rs`'s `cli_error`/`convert_error` special-
#                      case these on the *wrapped* library error before
#                      consulting `TABLE`, and the `DYNAMIC` list in its test
#                      module cross-checks against these rows.
#
# Two call sites can share `(command, code)` but differ in `exit` or `hint`
# — both shapes get their own row. A hint that is *conditionally present*
# depending on a field's value (`CellStampError::NotAnAnchor`'s `anchor:
# Option<...>` — hinted when `Some`, hint-less when `None`) is recorded as
# `dynamic:` once; the "sometimes no hint at all" branch is part of what
# `<what>` documents and what `compat.rs`'s special-case arm must reproduce
# (see `stamp STAMP_CELL_NOT_ANCHOR` below).
#
# Compound-condition arms (a legacy match on more than one field/predicate,
# not a single enum variant) are marked `[compound: <condition>]` in a
# trailing comment on their own line directly above the row, so a reviewer
# does not mistake them for a value that fell through to a wildcard `_`/
# `other` arm. Every such arm already has its own dedicated CLI code in the
# source (never lumped under a catch-all), so no row's `hint`/`exit` reflects
# more than one call site's actual behavior.
#
# `stamp-plan` is deliberately narrow (2 rows) even though the legacy
# `exit_stamper_error`/`exit_cell_stamp_error`/`exit_stamp_error` helper
# functions are *type*-reachable from `run_plan` (it also returns
# `Result<_, StamperError>`): `hwpforge::ops::stamp::stamp_plan`'s own
# `# Errors` doc (`crates/hwpforge/src/ops/stamp.rs`) states discovery never
# runs the admission gate and can only fail with `STAMP_CODEC_FAILED` — type
# signature overstates what the old `plan_bytes_v2` body actually produced.
# `stamp` (the apply command) keeps the full set: applying genuinely
# exercises admission, drift, coverage and naming checks.
#
# This file is the source of truth for "unchanged": regenerate only by
# re-auditing `src/commands/*.rs` and `src/error.rs`, never by copying
# `compat.rs`'s own table (that would make the check circular).
#
# ── This file holds only pre-W3-migration rows ──────────────────────────
# `new_codes.txt` (same directory) holds every `(command, code, exit, hint)`
# shape with no pre-migration call site to audit (a command or a code the
# migration itself introduced) — `validate` and `insert-para
# INSERT_TEXT_REQUIRED` today. `src/compat.rs`'s `snapshot_rows()` reads
# both files; keep them disjoint (a pair in both would be two conflicting
# "audited" answers for the same call site).
#
# ── Validation precedence (cheap argument guards vs. file I/O) ──────────
# Where a command's legacy `run()` validated an argument *before* touching
# the filesystem, a caller who passes both a bad argument and a missing/
# unreadable file sees the argument error, not a file error — an order
# `hwpforge::ops` cannot reproduce on its own (ops functions never touch the
# filesystem; only the frontend decides read-then-call-ops vs.
# validate-then-read-then-call-ops). Whichever lane wires a command below
# must keep read.rs argument checks measured against here as authoritative
# for the entry order, not a `cli_integration.rs` observation (a passing
# combined-failure test is `cli_integration.rs`'s job later; this file
# states what the pre-migration source proves it did).
#   read         VALIDATE-FIRST — `targets != 1` (READ_TARGET_REQUIRED) then
#                `paras.is_some() && section.is_none()` (READ_PARAS_WITHOUT_SECTION)
#                both run before `check_file_size`/`std::fs::read`.
#   fill         VALIDATE-FIRST — `parse_sets` (INVALID_SET/DUPLICATE_SET)
#                and the empty-map NO_VALUES check both run before
#                `check_file_size`/`std::fs::read`.
#   delete-para  VALIDATE-FIRST — `indices.is_empty()` (DELETE_NO_TARGET)
#                runs before `read_input` (`check_file_size`/`std::fs::read`).
#   insert-para  N/A — clap's `#[arg(required = true)]` on `--text` already
#                refuses an empty list before `run_insert` is ever called;
#                the old source has no argument check ahead of `read_input`.
#   convert (MD) VALIDATE-FIRST — `preset != "default"` (UNKNOWN_PRESET) is
#                checked before reading stdin or the input file.
#   to-pdf       VALIDATE-FIRST — `parse_discovery` (INVALID_DISCOVERY) runs
#                before `check_file_size`/`std::fs::read` (source comment:
#                "플래그 오류는 파이프라인 진입 전에 (독립 리뷰 L1 — .hwp 변환 후 exit 방지)").
#   to-json      VALIDATE-FIRST — the `.json` output-extension check
#                (INVALID_EXTENSION) is the first statement in `run()`,
#                before `check_file_size`/`std::fs::read`.
#   set-cell     READ-FIRST (opposite order) — `check_file_size`/
#                `std::fs::read` runs before `build_specs`'s argument
#                validation (INVALID_SET_CELL_ARGS/INVALID_SET_CELL_MAP).
#   stamp        READ-FIRST — both the target file and the `--map` file are
#                read before `MANIFEST_PATH_CONFLICT` (`output == &manifest_file`)
#                is checked, which runs last, after `parse_stamp_map`.
#   (all others) N/A — no argument validation ahead of file I/O in the
#                legacy source (diff, outline, fields, inspect, from-json,
#                patch, convert-hwp5, stamp-plan, templates, schema).
#
